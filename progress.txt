# session-task 进度记录（追加式）

## 2026-11-22 · fix: US-006 — HTTP 路由在活宿主上读不到数据

### 根因
`GET /api/session-task/tasks` 走 `store.workspace_root()`：宿主 HTTP 请求上下文里没有
agent，`qwenpaw.config.context.get_current_workspace_dir()` 返回 `None`，
`QWENPAW_WORKING_DIR` 也未设置，于是回退到**宿主进程 cwd** `C:\Users\Administrator\.copaw`，
而任务日志写在 `D:\QwenPawWorkSpace\default\session-tasks\events`。
路由本身正确，只是读错了根目录 → 恒返回 `[]` / 404。

次因：HTTP 侧用 channel 限定 id（`console:smoke-initiator-…`），而工具落盘的是裸 id
（`smoke-initiator-…`），`views._involves` 精确比较导致即便根对了也匹配不上。

### 修法（不另起 store，只做“解析根 + 绑定作用域”）
- `store.py`
  - `_WORKSPACE_OVERRIDE`（ContextVar）+ `workspace_scope(root)`：临时把
    `workspace_root()` 钉到某个根；`workspace_root()` 自身签名/默认行为不变
    （顺序变为 钉住的 scope → 宿主上下文 → 环境变量 → cwd）。
  - `_host_agent_workspaces()`：只读 `qwenpaw.config.load_config().agents.profiles[*].workspace_dir`，
    try/except 包住，取不到返回 `{}`（测试解释器没有 qwenpaw 也安全）。
  - `agent_workspace_for(session_id)` / `workspace_root_for(session_id)`：agent 配置 →
    `QWENPAW_WORKING_DIR` → `workspace_root()`。支持 `agent/session`、`agent:session`、
    裸 agent id 三种会话写法。
  - `candidate_roots(session_id)`：上面 + 旧根本 + 所有已配置 agent workspace（去重）；
    `events_dir_at()` / `tasks_path_at()` / `has_events_at()` 全部**不建目录**，探测无副作用。
  - 导出 `validate_task_id`（公开别名），供 HTTP 先判 400 再决定探哪个根。
- `http_api.py`
  - 两个路由都新增可选 `?workspace=<绝对路径>`：必须存在、必须是目录、必须含
    `session-tasks/`，否则 400（运维兜底，不是任意目录读取口）。
  - 按 `candidate_roots` 逐个探测：只有已存在 `session-tasks/events/*.jsonl` 的根才会
    真正 materialize（省掉在 10 个 agent workspace 里做无用功），第一个命中的根返回结果。
  - 全都落空时 `logger.warning` **一次**（每次请求一条），打印探过的根与 `?workspace=` 提示；
    列表仍返回 `[]`、详情仍 404（对外契约不变）。
  - 详情路由先 `store.validate_task_id()`，`nul` 这类保留设备名维持 400 而不是变成 404。
- `views.py`：`_session_aliases()` 把 `console:<id>` 与裸 `<id>` 视为同一会话，
  `_involves` 改为别名交集；`role=from/to/all` 语义不变。
- `tests/test_http_router.py`：新增 9 条（agent 配置注入假 workspace、无 agent 时回退到
  其它 agent workspace、`?workspace=` 列表/详情合法、3 种非法 `?workspace=` 400、
  列表与详情的 warning 各一条）；`workspace` fixture 默认把
  `_host_agent_workspaces` 打成 `{}`，避免开发机上的真实 agent workspace 污染用例。

## 2026-11-22 · feat: US-010 — runtime auto-pulse + stop guard（上游 API 缺失，走兜底）

> - **先查 API（结论：两个都没有）**：`D:\QwenPaw\Lib\site-packages\qwenpaw\plugins\api.py:49`
>   的 `PluginApi` 只有 `register_provider`(:82)、`register_startup_hook`(:128)、
>   `register_shutdown_hook`(:160)、`register_uninstall_hook`(:192)、
>   `register_workspace_created_hook`(:235)、`register_http_router`(:271)、
>   `register_control_command`(:302)、`register_prompt_section`(:325)、
>   `register_tool`(:399)、`register_skill_provider`(:514)。
>   `hasattr(PluginApi, "register_runtime_hook") == False`、
>   `hasattr(PluginApi, "register_agent_stop_handler") == False`；包内也没有 hook phase
>   枚举（`FINALLY` / `HookPhase` 只出现在注释和 `finally:` 里）。四个 hook 都是进程级
>   （启动/关闭/卸载/工作区创建），没有 turn 级回调。
> - **实现（新文件 `reliability.py`）**：`install(api)` 用 `getattr` 探测两条 API，缺失就
>   warning 并返回 `{"installed": [], "missing": [...]}`；`auto_pulse` 对
>   `views.iter_session_views(session, role="all", states=["working"])` 里的任务，本轮无
>   report/pulse 时经 `views.append_event_once` 写
>   `{"type":"pulse","value":note[:80],"auto":true,
>   "idempotency_key":"auto-pulse:<task>:<turn_key>"}`；`stop_decision` 返回
>   `{"decision":"BLOCK"|"ALLOW","blocked","continuation","task_id","attempt"}`，每任务最多
>   BLOCK 2 次，第 3 次放行，`continuation` 文案为
>   「任务 <id> 还在进行，请 task_report 或 task_pulse 后再结束」。
> - **「本轮」判定**：事件 `seq` 高水位（`_WATERMARK` = 上次 hook 结束时的最大 seq），
>   高于高水位的 `summary`/`pulse`/带 `note` 的 `state` 视为本轮活动。不用时间戳：事件
>   `at` 只有秒级精度（`store._now_iso` 用 `timespec="seconds"`），同秒两次写入无法区分。
> - **踩坑**：最初把 `state` 事件整体当活动，任务刚进 `working` 就被判「已汇报」，
>   auto-pulse 一次都不写；改为 `state` 必须带 `note` 才算。另：`submitted -> completed`
>   在状态机里非法，测试里建「已完成」任务必须经过 `working`。
> - **接线**：`plugin.py` 导入 `reliability`，`register()` 末尾调用 `_register_reliability(api)`，
>   整体包 try/except，任何异常都不影响六个工具。
> - **测试**：`tests/test_reliability.py` 17 例（FakeApi 有/无/半有/注册即抛异常四种 install
>   路径；pulse 写入与 80 字截断；无 working 不写；同 turn 只写 1 条；下一轮再写；
>   BLOCK 第 1/2 次、第 3 次放行；已 report 放行；已 pulse 放行；auto-pulse 后放行；
>   无 working 放行；跨任务计数独立；reset 后磁盘幂等仍生效）。
>   `pytest tests -q` 连续 2 次 `448 passed, 3 skipped`；`compileall` 两解释器
>   （`D:\Miniconda\python.exe` / `D:\QwenPaw\python.exe`）通过。
> - **README**：新增「二期待做：stop handler / runtime hook（上游 API 未暴露）」一节，
>   含 API 对照表、`install` 返回值、seq 高水位判定法，以及「上游提供后怎么接」。
> - 未改 `prd.json`（按要求）。
